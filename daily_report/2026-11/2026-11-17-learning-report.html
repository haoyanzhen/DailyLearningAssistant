字段级错误定位中的路径表达与错误聚合

完整讲解

字段级错误定位中的路径表达与错误聚合，核心是把 API 失败从一句“请求失败”变成可定位、可分类、可聚合的契约对象。状态码表达失败类别：403 通常表示权限不足，409 通常表示资源冲突，422 通常表示请求语义校验失败。字段路径表达错误位置，例如 items[0].source_id 表示第 0 个条目的 source_id 字段出错。错误聚合表达一次请求中的多个违规，而不是只返回第一个错误。未知字段拒绝表达契约边界，避免部分接口静默忽略未知字段。一个外卖下单接口如果只返回“订单创建失败”，用户会反复猜测是手机号、地址、优惠券还是备注有问题；字段级错误就像餐厅退菜单，直接列出第 2 项辣度不能为负数、地址缺少门牌号、优惠券字段不在允许列表。当前无 diff，错误结构、字段路径、OpenAPI 策略和前端映射实现均待确认。

原理逻辑

  1. 状态码先回答“失败属于哪一类”，让调用方选择权限处理、冲突处理或校验修正。
  2. 字段路径再回答“失败发生在哪个位置”，使数组下标、嵌套对象和未知字段都能被机器解析。
  3. 错误聚合和未知字段拒绝把多个违规与契约边界一次性暴露，避免只返回第一个错误或静默忽略。

具体例子

删除关联接口返回 422，响应体可设计为 code='VALIDATION_FAILED'，errors 数组包含 path='items[0].source_id' 的 NOT_FOUND、path='items[1].reason' 的 TOO_LONG、path='unknown_field' 的 ADDITIONAL_PROPERTIES，前端根据 path 把错误显示到对应输入项。

常见误区

  • 认为只要返回 422 就算清楚，或者只返回第一个错误。
  • 把未知字段静默忽略，或者把 409 和 422 混用，错误文本只给人看而不写成机器可解析路径。

概念关联

关联概念关系说明
集合差异分类中的缺失、多余、重复与越界判定为集合差异提供机器可读的错误字段，使 missing、extra、duplicate、out_of_scope 能被调用方解析并决定重试或人工处理。
模型下线场景中的依赖失效检测与错误归属共享错误契约，使模型不可用、版本冲突和权限问题都能用明确错误码和字段路径表达。

集合差异分类中的缺失、多余、重复与越界判定

完整讲解

集合差异分类中的缺失、多余、重复与越界判定，核心是把“两个集合不相等”拆成可判定事实。missing 表示期望有而观察无，extra 表示观察有而期望无，duplicate 表示观察中同一元素出现次数超过期望，out_of_scope 表示观察项不属于当前请求范围。无 snapshot_id 时，total 和 cursor 必须绑定同一逻辑集合，否则分页过程中集合边界变化会让差异判定失真。重试策略也要基于差异类别裁决：来源异常可能适合重试，游标失效可能需要重新定位，集合缺失可能需要人工处理或重新拉取。超市盘点时，账本有 10 件商品，货架数出 9 件，其中 1 件重复、1 件不属于本店、1 件缺失；只说“对不上”无法处理，必须分类成缺什么、多什么、重复什么、越界什么。当前无 diff，集合比较、游标绑定和重试分类实现待确认。

原理逻辑

  1. 集合比较不能只输出布尔结果，要输出可分类的差异事实，才能驱动后续动作。
  2. 无快照时，total 与 cursor 必须绑定同一逻辑集合，否则分页漂移会污染 missing、extra、duplicate 和 out_of_scope 判定。
  3. 重试裁决要区分来源异常、游标失效和集合缺失，避免把提供方故障误报为集合不完整。

具体例子

期望集合 E={a,b,c,d}，观察集合 O={a,a,c,e}，可判定 missing={d}、duplicate={a}，e 可归为 extra 或 out_of_scope；若提供方返回 500，则应归为来源异常而不是 missing。

常见误区

  • 认为 total 相同就代表集合完整，或者分页请求成功就代表数据完整。
  • 把提供方网络故障误报为集合缺失，或者在没有 snapshot_id 时仍假设 total 与 cursor 指向稳定不变集合。

概念关联

关联概念关系说明
字段级错误定位中的路径表达与错误聚合依赖字段级错误定位把差异结果表达为机器可读字段，调用方才能判断失败原因并决定重试或人工处理。
模型下线场景中的依赖失效检测与错误归属共享重试裁决逻辑，需要区分集合缺失、游标失效、来源异常和上游依赖失效，避免误报。

模型下线场景中的依赖失效检测与错误归属

完整讲解

模型下线场景中的依赖失效检测与错误归属，核心是 LLM 请求绑定具体模型、版本或目录状态后，上游依赖失效时应显式失败，而不是静默降级或换模型。参数冻结请求通常依赖请求时确定的模型、版本或目录状态；如果模型下线，继续执行可能造成语义漂移。失败检测点可以分层：模型目录表达模型不可用，请求网关拦截依赖失效请求，业务服务结合请求上下文返回更具体错误。错误归属要明确谁检测、谁返回错误、谁通知调用方。版本比较或 CAS/乐观锁用于检测请求时依赖状态是否仍成立；如果版本窗口冲突，应返回可识别错误。幂等机制用请求摘要、幂等键或服务端去重表，避免同一冻结请求重试产生重复副作用。你预约了一位医生看诊，挂号时医生已排班，但看诊前医生临时停诊；医院不能悄悄换另一位医生，而应明确告知原医生停诊，并说明是排班系统、挂号网关还是科室系统发出通知。当前无 diff，模型目录、网关、业务服务、CAS 或幂等去重实现待确认。

原理逻辑

  1. 参数冻结请求依赖请求时确定的模型、版本或目录状态，依赖失效后继续执行可能造成语义漂移。
  2. 失败检测要分层并归属：模型目录、请求网关和业务服务分别承担不同检测、返回和通知职责。
  3. CAS/乐观锁检测状态版本窗口是否仍成立，幂等键和去重表保证重试不产生重复副作用。

具体例子

冻结请求包含 model='gpt-x'、model_version='2026-10'、state_revision=7，执行前模型目录把该版本下线，CAS 比较 state_revision 失败，网关返回 409，错误体包含 code='MODEL_DEPENDENCY_INVALID'、attribution='model_catalog'、retryable=false 和 request_fingerprint，重试同一幂等键时返回原失败回执，不重复产生副作用。

常见误区

  • 模型下线时自动切换到其他模型或默认模型，把依赖失效当成普通超时。
  • 只返回“服务不可用”而不说明是模型目录、网关还是业务服务，或者重试没有幂等导致重复创建、重复计费或重复写入。

概念关联

关联概念关系说明
字段级错误定位中的路径表达与错误聚合依赖字段级错误定位，使模型不可用、版本冲突和权限问题都能返回可解析错误而不是通用错误文本。
集合差异分类中的缺失、多余、重复与越界判定与集合差异分类共享重试裁决，需要区分集合缺失、游标失效、来源异常和上游依赖失效，避免把模型下线误报为集合不完整。
