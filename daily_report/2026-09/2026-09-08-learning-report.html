悬空关系的瞬态性：分支重新指向后对象立即重新进入可达闭包

Transient dangling objects and re-entering reachable closure

对象不会天生悬空，它只是暂时失去引用边；只要分支或标签重新指向它，它就会瞬间回到正式可达集合。

核心要点

  • 悬空对象本身完好，只是当前没有任何分支或标签引用它。
  • 分支或标签重新指向该对象时，Git 立即将其纳入可达集合，无需重写对象文件。
  • 对象是否悬空是随 refs 改变而不断更新的临时关系，不是固定属性。
计算机科学 / 软件工程 ★★★

物理存在但不被索引发现的对象：pack 无 idx 时 fsck 面对的是目录盲区

Physically existing but index-invisible objects: pack without idx as directory blind spot

fsck 不扫描硬盘上的所有字节，而是按索引目录查找对象；一个没有登记入口的 pack，即使物理存在也等于不可见。

核心要点

  • 对象必须通过 idx 或 midx 登记后才能被 Git 查找，否则即使 pack 存在也如同不存在。
  • fsck 报告 missing 不一定是磁盘文件缺失，也可能是该对象没有可解析入口。
  • 未生成 idx 的 pack 相当于“未发布”，会让 fsck 认为对象缺失。
软件工程 / 计算机科学 ★★★★

并发写总索引时的锁边界：repack 与 multi-pack-index write 不能各自清点旧 pack

Lock boundary for concurrent total-index updates: repack and multi-pack-index write must not independently prune old packs

要让并发的 repack 安全，锁不是锁住 pack，而是锁住“改写总索引并清点旧 pack”的入口。

核心要点

  • 旧 pack 能否删除由总索引是否仍引用它决定，运维命令必须基于最新包集合判断。
  • repack 与 multi-pack-index write 若各自清点旧 pack，可能互相误删仍在使用的对象。
  • 应将“写总索引 + 清点旧 pack + 删除不再被引用的 pack”放入同一把锁保护的临界区。

精读文章 · 计算机科学 / 软件工程

悬空关系的瞬态性：分支重新指向后对象立即重新进入可达闭包

完整讲解

先想象一张城市地图：对象是地图上的景点，分支和标签是官方旅游路线。一个景点如果没有被任何路线覆盖，它就是“游离”的，也就是悬空对象。但悬空并不是景点自身变坏了，它仍然是完好的，只是当前没有路线连到它。如果某一天官方路线改动了，把一条新路线指向这个景点，它立刻又成为当前正式路线的一部分。Git 的对象也是一样：一个提交对象成为悬空，往往是因为分支指针被移动、离开了它；但只要某个分支或标签重新指向这个提交，Git 会立刻把它纳入“当前可达”的集合。整个过程不需要重写对象、不需要移动文件、不需要修改对象 ID，变的只是引用关系这一条线。这个动态视角非常重要：如果你在某一个瞬间看到对象“没人引用”，不能因此断定它永远没用；它可能下一秒就被新分支捡回去。

原理逻辑

  1. 可达闭包由当前 refs 决定，refs 改变即改变对象是否被包含。
  2. Git 不移动对象文件，仅通过添加或更新引用记录来扩展可达集合。
  3. 对象 ID 不变，内容寻址使重新引用无需修改对象本身。

具体例子

一个剧本曾被导演剪出正片，但后来版本回退，这个片段变成了素材库里的“未采用片段”。某天续集导演在废片里发现了这段剧情，把它重新编入正片，它就从素材变成了当前故事线的一部分。片段本身一字未改，变化的是“哪一条官方时间线正在使用它”。

常见误区

  • 误以为“悬空对象”等于“坏对象”或“垃圾对象”，实际上悬空对象通常内容完好。
  • 误以为从悬空变回被引用需要把对象“移回来”，其实只是引用文件里多了一行哈希。

概念关联

关联概念关系说明
被引用边界与悬空对象前一天定义了完整性检查只要求“被已发布引用可达的对象”必须存在，今天从时间维度说明这个边界随引用更新而动态变化。
物理存在但不被索引发现的对象无索引的 pack 对象没有被发布，即使物理存在也不可见；悬空对象若被重新引用则立刻可见，两者都依赖当前逻辑视图而非文件存在。

精读文章 · 计算机科学 / 软件工程

物理存在但不被索引发现的对象：pack 无 idx 时 fsck 面对的是目录盲区

完整讲解

在 Git 中，一个对象要被读取，必须先经过“查找表”。松散对象通过目录路径定位，pack 中的对象则通过 idx 或 multi-pack-index（midx）定位。idx 就像 pack 的目录清单，记录了这个 pack 里每个对象 ID 以及它在 pack 中的偏移量。若一个 pack 文件躺在 .git/objects/pack/ 里，却没有对应的 idx，也没有被 midx 登记，Git 在查找对象时根本不会去扫描这个 pack 的内部。于是，即使这个 pack 里保存着完整的数据，在 Git 的逻辑视图里它也像不存在一样。fsck 做完整性检查时，沿着引用图逐个遍历对象，每一步都要用查找表定位对象所在位置。如果某对象只存在于无 idx 的 pack 中，fsck 会报告“missing”。这不是说磁盘上的文件被删除了，而是说“在当前索引体系中找不到可解析入口”。这就像一间没有编目卡片的库房，书确实放在里面，但馆藏系统不知道，读者也检索不到。

原理逻辑

  1. Git 对象查找依赖索引表，不扫描目录内全部物理字节。
  2. 没有 idx 或 midx 登记的 pack 无法参与对象解析，形成目录盲区。
  3. fsck 的 missing 表示在当前可解析入口中找不到，而非物理文件一定被删。

具体例子

图书馆大扫除时，管理员在书架背面发现一本没有登录到编目系统的旧书。馆藏系统里查不到它，读者按索书号找不到它，将来盘点时也不会把它算成馆藏。直到有人给这本书补做登记卡、录入系统，它才从“物理存在但馆藏缺失”变成真正可借阅的书。Git 的 pack 和 idx 就是这个关系：pack 是书，idx 是编目卡，缺了编目卡，fsck 就看不见这本书里的任何字。

常见误区

  • 把 fsck 报告 missing 直接理解为磁盘上没有任何数据。
  • 以为 Git 会自动扫描无索引的 pack 并纳入检查，实际上需要显式索引。

概念关联

关联概念关系说明
并发写总索引时的锁边界pack 必须先通过索引发布才能被读到；写锁保证清点旧 pack 时看到的包集合是一个不发生跳变的视图。
delta 对象的外部依赖基对象不在可解析集合时，即使字节存在也无法还原，本质都是对象未被当前可解析目录成功暴露。

精读文章 · 软件工程 / 计算机科学

并发写总索引时的锁边界：repack 与 multi-pack-index write 不能各自清点旧 pack

完整讲解

一个 pack 文件能否被删除，不由它自己在磁盘上是否老旧决定，而由对象库的总索引决定。总索引维护着“当前有哪些 pack、每个对象在哪个 pack 的哪个偏移”的查找关系。若某个 pack 仍被总索引引用，它就有资格继续服务对象查找；若总索引已经切换到新集合，它才可能成为待回收对象。现在考虑两个维护命令同时运行：git repack 会生成新 pack，再更新总索引并清理不再需要的旧 pack；git multi-pack-index write 也会根据当前 pack 目录重写总索引。如果它们没有先获得同一把写锁，就可能发生危险：repack 认定某些旧 pack 不再需要并准备删除，而 multi-pack-index write 刚刚读到的目录状态显示这些旧 pack 仍在仓库中，于是把其中一个旧 pack 也写进新的总索引。最终，repack 删掉旧 pack，但新总索引还引用它，对象就永久丢失了。正确的做法是把“写总索引 + 清点旧 pack + 删除不再被引用的 pack”放入同一个临界区，由同一把锁保护。锁的边界不是单个 pack 文件，而是总索引的写入口。拿不到锁的命令必须等待，等拿到锁后再按最新状态清点，才不会误删另一个命令刚刚发布的内容。

原理逻辑

  1. 对象库维护的本质是安全地更新总索引而后回收废弃 pack，而不是直接操作文件。
  2. 若两个命令没有共享同一把锁，清点旧 pack 的决策会基于过期视图，导致误删。
  3. 锁必须覆盖“读当前状态、写新总索引、清点并删除”整体过程，才能原子切换包集合。

具体例子

自助餐厅的后厨有两位管理员同时修改今日菜单。管理员甲按照昨晚的旧菜单，准备把一盆牛肉丸当成“即将过期食材”清掉；管理员乙此时正打算把同一盆牛肉丸写进新的今日菜单。如果甲只给牛肉丸的盆子贴了标签“处理前需确认”，乙依然可以绕过这个标签更新菜单。真正有效的办法是规定：任何人要修改今日菜单，必须先拿到唯一一张“菜单修改卡”。甲拿到卡后统一清点食材，乙排队等待；甲完成后，乙再拿到卡时看到的是最新菜单，自然不会把已经被清掉的食材再写进去。Git 的 repack 和 multi-pack-index write 也需要这种“总索引写卡”。

常见误区

  • 以为并发 repack 最多浪费磁盘，不会破坏数据；实际可能永久丢失对象。
  • 以为锁应锁住 pack 文件本身；但其他命令可通过更新总索引引用该 pack，锁文件不能阻止视图变化。
