C1 设计承诺与实现/运行证据分层

完整讲解

这个概念的底层意思是：一句工程结论必须先说清楚，它到底是“我们计划这样做”“代码或配置里已经有一部分这样做”，还是“实际运行和测试已经证明这样做有效”。设计文档里的验收设计，像建筑图纸上的消防通道，只能证明设计师承诺这里应该有一条通道；局部 diff 像工地里出现了一扇门框，只能证明实现有动作；只有检查、测试或运行记录，才能证明通道真的能走人。历史材料中的“验收设计不是已运行测试”“未实现”“工程接入不等于运行验收”“未建库、未运行并发或恢复测试”，都在提醒读者不要把不同层的证据混成一句话。

原理逻辑

  1. 证据层级从弱到强可表述为设计承诺、实现状态、运行证据，报告结论只能与手中证据同级。
  2. 字段被返回、某次提交改了文件、设计文档写了验收方案，都只能作为线索，不能自动升级为功能已完成并验证。
  3. 准确措辞应分别标明设计层是否有方案、实现层是否有局部 diff、运行层是否有测试、CI 或端到端结果。

具体例子

历史设计文档写了“验收设计完成”，代码 diff 里也出现相关字段；报告只能写成设计层有验收方案记录、实现层可见局部 diff、运行层未提供测试、CI 或端到端结果，不能直接写“已通过验收”。

常见误区

  • 看到某个字段被返回或某次提交改了文件，就写成“功能已完成并验证”。
  • 看到设计文档写了验收方案，就写成“已通过验收”，忽略运行层证据尚未提供。

C11 业务修订与内部执行 epoch 的语义区分

完整讲解

这个概念要解决的是“版本号长得像，但意思完全不同”的问题。业务修订 revision 是给业务对象用的、对客户端有意义的版本标识，常用于并发控制和审计；内部执行 epoch 是系统内部用来隔离某一次执行、重跑或任务实例的序号，它不是客户端 revision。可以用文档来打比方：revision 像一本书的第 3 版，读者和图书馆都用它判断内容版本；epoch 像印刷厂这次印刷任务的批次号，只对内部生产流程有意义。历史材料还强调：身份由服务端生成 UUID，时间统一使用 UTC；可变业务对象有 revision、created_at、updated_at；不可变事实不强制伪造 updated_at；API DTO 不能直接当作 ORM 保存对象；凭据更新不能改写历史业务配置快照。

原理逻辑

  1. 版本语义分离：业务修订回答“对象内容是哪一版”，执行序号回答“这是哪次执行、重跑或任务实例”。
  2. 持久化边界：DTO 是传输结构，ORM 是保存结构，DTO 里出现 revision 字段不等于已经落库。
  3. 审计边界：服务端 UUID、UTC 时间、历史配置快照和凭据更新都要保持语义稳定，不能因一次重跑或凭据更新改写历史。

具体例子

某次运行实例的 epoch 是 7，而业务对象的 revision 是 3，报告不能写成“业务对象 revision 变成 7 了”；一个 API DTO 里带着 revision 字段，但 ORM 保存对象并未落库，也不能声称业务修订已持久化。

常见误区

  • 看到任何递增数字都当成业务版本号，把执行 epoch 当作客户端可以提交的 revision。
  • 看到 DTO 里有 revision 字段就认为已经保存到 ORM；更新用户凭据时顺手改写历史业务配置快照。

概念关联

关联概念关系说明

无变化、未采集、失败三态不可互相冒充执行序号可以帮助定位某次采集或执行，但不能替代负证据报告中的采集状态语义。
提案与凭证、标识与授权提案不等于提交，标识命中不等于授权，同样，执行 epoch 不等于业务 revision，DTO 不等于 ORM 事实。

无变化、未采集、失败三态不可互相冒充

完整讲解

这个概念处理的是负证据：当我们说“没有发现变化”时，到底发生了哪种情况？第一种是“确认无变化”，也就是确实采集了、比较了，结果显示没有差异；第二种是“未采集”，也就是根本没有去看，或者数据源没有覆盖；第三种是“失败”，也就是尝试采集或比较时遇到了错误。这三种状态看起来都可能表现为空结果，但含义完全不同。就像医生做检查：身体健康、没有做这项检查、检查机器坏了，不能都写成“没问题”。

原理逻辑

  1. 负结论至少要有采集状态、覆盖范围、比较方法和未覆盖项，空结果本身不是结论。
  2. 空白字段、空数组、没有告警、没有 diff 可能分别对应确认无变化、未采集或失败，不能统一渲染成“无变化”。
  3. 报告应保留失败原因和覆盖边界，避免把部分仓库、部分时间段或部分数据源的结论扩大为全局结论。

具体例子

今天多个 work_summary 写明“无新增变化；仅保留仓库状态”。这只能作为这些文件范围内的确认无变化证据，不能自动推广成“所有仓库、所有运行环境都确认无变化”；某个仓库没有采集应写“未采集”，采集工具报错应写“失败”。

常见误区

  • 空白字段、空数组、没有告警、没有 diff，就一律写成“无变化”。
  • 当前目录没看到某条目，就认为它不存在；实际上可能被归档或未采集。

概念关联

关联概念关系说明
