D2 复合排序键与游标分页的全序稳定性

完整讲解

游标分页不是记住第几页，而是记住上一页最后一条记录在排序中的位置。若只用 created_at 等时间字段排序，并列值会使数据库返回顺序不稳定，下一页条件用大于或大于等于都可能漏项或重复。把 created_at 与唯一 id 组成复合排序键，按一致方向形成更稳定的全序，才能准确定位边界。全序稳定并不自动解决排序字段被修改、翻页期间插入新记录以及快照一致性等问题，因此分页契约还要说明排序字段变化时游标是否失效、是否使用快照、是否选用不可变排序键。

原理逻辑

  1. 游标记录的是排序位置边界，不是页码偏移量。
  2. 单字段时间排序可能出现并列值，需用唯一 id 等字段补足，形成更稳定的全序。
  3. 全序稳定只解决定位条件，排序字段变化、插入可见性和快照一致性仍须由分页契约规定。

具体例子

三条记录都在 10:00，id 分别为 1、2、3，下一条是 10:01、id 为 4。只用 created_at 做游标时，大于 10:00 会漏掉 id 3，大于等于 10:00 又可能重复前两条；改用 created_at 加 id 的联合键，游标记为 10:00 加 id 2，才能稳定继续找到 id 3 和 id 4。

常见误区

  • 以为游标分页只是把页码换成 id。
  • 以为 created_at 一定唯一，单字段游标就能自动保证全序稳定。
  • 以为全序稳定会自动解决排序字段修改和跨页快照不一致。

概念关联

关联概念关系说明
D3 幂等键与请求体指纹的绑定语义分页联合键为记录提供稳定定位，幂等键加请求体指纹为请求意图提供稳定标识，二者都在设计可复核的等价类边界。
D4 资源槽生命周期与状态迁移互斥游标需要稳定全序来避免相邻翻页间的重复或漏项，资源槽接管也需要稳定状态迁移来避免相邻调度观察间的双持槽。
D1 修订号比较与写入的原子性边界修订号比较与写入的原子性边界强调检查和写入不可拆，和游标定位需要稳定条件一样，都反对把关键判断建立在易变窗口上。

D3 幂等键与请求体指纹的绑定语义

完整讲解

幂等键像给有副作用的业务请求发一个编号，重复提交时服务端可尝试识别同一次请求的重复发送。但幂等键只证明客户端声明同一编号，不能证明请求内容相同；同一个键可能被不同请求体复用。因此需先规范化请求体并计算指纹，服务端存储键、指纹、首次结果或处理状态。同键同指纹时可按契约返回首次结果或同样处理结果；同键不同指纹时应明确拒绝、覆盖或返回首次结果等冲突策略。幂等键有效期以及过期后的重复识别规则也必须定义。幂等键负责标识请求意图，请求体指纹负责证明内容同一，二者不能互相冒充。

原理逻辑

  1. 幂等键标识请求意图，请求体指纹证明内容同一，二者共同划定重复请求的等价类。
  2. 同键同指纹与同键不同指纹要有不同处理语义，冲突策略必须写进契约而不能靠猜。
  3. 幂等键有效期是时间边界，过期后的重复提交通行规则会影响同一请求的判定。

具体例子

客户端第一次发送付款请求，幂等键是 K1，请求体是金额 100。网络超时后仍用 K1 和金额 100 重试，服务端可以返回第一次结果，避免重复扣款。若另一个请求也带 K1，但金额变成 200，服务端不应默默返回第一次的 100 结果，而应按契约返回冲突，提示同一个幂等键被不同请求体复用。

常见误区

  • 以为幂等键相同就代表请求内容相同。
  • 以为幂等就是服务端永远不重复执行。
  • 忽略同键不同体、有效期和过期后的重复识别规则。

概念关联

关联概念关系说明

D4 资源槽生命周期与状态迁移互斥

完整讲解

资源槽可理解为执行许可证，构建、任务或 Run 只有拿到它才能使用受限资源。资源槽不是普通布尔标记，而是与生命周期状态绑定：queued 通常不占槽，running 可能占槽，paused 是否继续占槽必须由规则写清。paused 长时间不恢复可能一直占槽，因此需要过期机制；但过期释放后恢复时可能需要重新校验和重新申请。queued 长期等不到资源也需定义超时、取消或重新校验权限。重跑场景中，旧 Run 释放槽与新 Run 接管槽必须在同一个可复核状态迁移边界内完成，否则调度器可能观察到旧 Run 未释放、新 Run 已获取的双持状态。资源槽必须由状态机迁移约束，占用、释放、过期和接管都要有明确边界。

原理逻辑

  1. 资源槽持有关系必须与 queued、running、paused 等生命周期状态显式绑定。
  2. 占用、释放、过期和接管都需由状态迁移规则约束，避免标签冒充实际持槽状态。
  3. 重跑时旧 Run 释放与新 Run 接管应在同一可复核边界内原子完成，防止并发拆开关键状态变更。

具体例子

Run A 处于 paused 并占着资源槽，用户触发重跑生成 Run B。合法迁移应把 A 从 paused 转为释放状态，同时把 B 从 queued 转为 running 并获得槽，这两个结果在可复核边界内一起生效。若先让 B 获得槽、过一会儿才释放 A，中间就可能出现 A 和 B 同时持槽的双持状态。

常见误区

  • 以为 queued、running、paused 这些标签自动等于资源槽状态。
  • 以为 paused 一定继续占槽，或者一定可以随时释放。
  • 以为设计契约或状态标签能自动证明实际持槽状态，不需要状态迁移规则和运行证据。

概念关联

关联概念关系说明
D1 修订号比较与写入的原子性边界旧 Run 释放槽与新 Run 接管槽的原子迁移，和修订号比较后写入一样，都要求状态变更不可被并发操作拆开。
D3 幂等键与请求体指纹的绑定语义paused 长时间占槽的过期和幂等键有效期都需要定义时间边界，并说明过期后的重新判定规则。
D2 复合排序键与游标分页的全序稳定性资源槽状态迁移需要可复核的当前状态，类似游标分页需要稳定全序来避免同一对象在相邻观察之间被误认。
