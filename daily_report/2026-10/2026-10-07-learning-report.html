只读监控记录的最小脱敏边界

完整讲解

只读监控记录的最小脱敏边界，讲的是监控报告应该记录到什么程度。只读监控本身不修改仓库，但它会生成日志、日报、状态表，这些内容会被人工阅读，也可能被 Agent 继续加工。因此记录字段既要足够说明状态，又不能把敏感信息扩散出去。判断一个字段是否该记录，可以问三个问题：是否用于判断访问状态、指针状态或详情状态；是否必须保留原文才能复核；是否可以用占位符、摘要或相对路径替代。如果答案是否定的，就应该脱敏或不记录。脱敏边界只规定记录内容，不证明访问成功，不证明 ref 未变，也不证明提交事实。

原理逻辑

  1. 最小暴露：只保留判断状态所必需字段，避免把敏感信息扩散到日志、日报和状态表。
  2. 字段三问：是否用于状态判断、是否必须保留原文、是否可用占位符或相对路径替代。
  3. 边界分离：脱敏解决记录安全，不替代访问事实、指针事实或提交事实。

具体例子

例如监控某仓库 main ref。可记录字段包括 repo_id、ref=main、previous_sha、current_sha、access_status=success、pointer_status=unchanged、window_start 和 window_end。需要脱敏字段包括远端 URL 中的 token、SSH 私钥路径、个人邮箱、完整访问命令和错误详情中的凭据。如果首次访问失败、重试成功，可记录 access_status=success、retry_status=success、pointer_status=unchanged，同时把错误信息中的敏感部分替换为 [REDACTED]。

常见误区

  • 认为只读监控不会修改代码，所以记录可以随意完整。
  • 把所有路径都脱敏到无法复核，或者把没记录敏感信息当成访问成功的证据。

概念关联

关联概念关系说明

重试事件下的状态保留与措辞断言

完整讲解

重试事件下的状态保留与措辞断言，处理的是事件序列和状态覆盖问题。一次监控检查可能先访问失败，再重试成功，最后读到 ref 指针未变；也可能某个 ref 访问失败，而其他 ref 未变。如果系统只保存最终状态，就会丢失曾经失败的事实；如果只保存失败，就会丢失重试成功的事实。因此需要把状态拆成多个正交字段，例如 access_status、retry_status、pointer_status 和 detail_status。事件应该追加而不是覆盖，当前状态由事件派生，历史轨迹可审计。措辞断言要求自然语言结论必须受字段组合限制：只有 access_status=success 且 pointer_status=unchanged 时，才能说被监控 ref 未变；如果 access_status=failure 或 pointer_status=unknown，只能说访问失败或详情未知。局部 ref 未变或访问失败不能扩大为整个仓库没有工程进展。

原理逻辑

  1. 事件追加：第一次失败、重试成功、指针未变等事实应保留为事件序列，而不是被最终状态覆盖。
  2. 字段正交：访问状态、重试状态、指针状态和详情状态分别表达不同维度，避免互相覆盖。
  3. 措辞断言：自然语言结论必须由字段组合触发，证据不足时措辞必须降级。

具体例子

例如检查仓库 A 的 main 和 develop。main 首次访问失败，重试成功，读到 main 指针与基线相同；develop 首次访问成功，指针与基线相同。允许措辞是 A 仓库 main 与 develop 在检查窗口内 ref 指针未变，且 main 曾发生访问失败并重试成功。不允许措辞是 A 仓库无工程进展，除非另有窗口内提交证据或人工确认。如果 main 重试后仍失败，则 main 的 pointer_status 应标为 unknown，不能写 main 未变。

常见误区

  • 认为最终状态最重要，所以历史事件可以覆盖。
  • 把重试成功当成提交内容已确认，或把某个 ref 访问失败扩大为仓库整体无进展。
  • 认为措辞只要看起来谨慎就行，不写成可检查规则。

模拟结果可比性前提的版本一致性检查

完整讲解

模拟结果可比性前提的版本一致性检查，关注的是比较前的前提条件是否成立。胜率、平衡结果或模拟输出不是孤立数字，它们依赖样本数、随机种子、参数版本和关卡数据版本。如果两组结果的样本数不同、随机种子不同、参数版本不同或关卡数据版本不同，那么结果差异可能来自样本波动、随机路径、规则变化或关卡变化，不能稳定解释为某个参数更优。版本一致性检查可以看作实验条件对齐：结果文件应记录 sample_count、seed、params_version 和 level_data_version 等字段，比较器先读取这些字段，再决定比较强度。若字段一致，可以进入差异分析；若只有参数版本不同，其他字段一致，可以讨论参数影响；若多个版本不一致，结果只能作为观察线索，不能写成选择依据。

原理逻辑

  1. 实验条件对齐：比较前必须先确认样本数、随机种子、参数版本和关卡数据版本是否一致。
  2. 比较强度分级：字段一致可进入差异分析，单变量不同可讨论该变量影响，多变量不同只能作为观察线索。
  3. 结论降级：前提不成立时，结果不能直接支撑参数优劣或平衡选择，只能保留为待验证线索。

具体例子

例如 result_A 记录 sample_count=1000、seed=42、params_version=v1、level_data_version=v1、win_rate=0.52；result_B 记录 sample_count=1000、seed=42、params_version=v2、level_data_version=v1、win_rate=0.55。样本数、随机种子和关卡数据版本一致，只有参数版本不同，因此可以比较参数 v1 与 v2 的影响，但仍需保留波动说明。若 result_C 的 level_data_version=v2，则 result_A 与 result_C 不能直接比较，只能标记为关卡数据版本不一致的观察线索。

常见误区

  • 只记录结果不记录版本，或认为样本数足够大就能弥补版本不一致。
  • 把随机种子不同当成可忽略，或认为旧平衡选择可以自动适用于新关卡数据。
  • 把结果文件存在当成可比性成立。
